## 未完成

### P0：决定能否日常使用

1. **GPT-SoVITS 专属音色验收**
   - 已完成 SoVITS 12 epoch、GPT 10 epoch，权重在 `SoVITS_weights_v2/` 和 `GPT_weights_v2/`；
   - 已加载到 `api_v2` 并生成 `trained.wav`；
   - 待试听对比 zero-shot，并在 QQ 里确认新权重的语音条。

2. **QQ 网关稳定性**
   - 现场出现过 `ECONNREFUSED 8081`，表现为网关进程退出；
   - 已给 tick 加异常隔离，但还没有进程守护/自动重启；
   - 建议用计划任务或 supervisor 守护 `qq run`，并保留标准错误输出。

3. **微信私聊现场验收**
   - 需要真实 wxid 加入 `allowedPrivateIds`；
   - 确认私聊表结构、原生发送和回执；
   - 目前微信私聊只支持文字。

4. **语音质量主观评估**
   - 已确认客户端显示为语音条；
   - 还需判断 zero-shot 音色是否足够像数据集，再决定是否训练专属权重；
   - 失败回退文字和私聊 record 已覆盖。

### P1：可维护性

1. **统一配置管理**
   - 当前配置分散在 `.env`、`gateway.json`、NapCat `onebot11_*.json`；
   - 建议增加只读 `config check`，汇总各配置来源和缺失项，不输出 secret。

2. **进程管理**
   - 启动脚本只负责拉起，没有 PID 文件/自动重启；
   - 建议增加 `status`、`stop`、`restart` 子命令或 Windows 服务。

3. **私聊白名单管理**
   - 微信 wxid 需要手动查 `contacts` 后写 JSON；
   - 建议增加 `admin private allow/deny/list`，写入控制库而不是改 JSON。

4. **测试与 CI**
   - 目前 403 项离线测试，缺少真实平台集成测试；
   - 建议为 QQ OneBot 假服务器、NapCat webhook、微信私聊表结构增加回归夹具；
   - CI 只跑离线测试，不连接真实账号。

5. **可观测性**
   - 控制台日志不落盘；
   - 建议增加结构化状态计数、错误码统计和轮转日志（不记录聊天正文）。

### P2：能力扩展

1. **真 @ 提醒**
   - 微信 native hook 和 QQ OneBot 都需要额外发送元数据；
   - QQ 可用 `at` 消息段，微信需要扩展发送协议；
   - 在当前“纯文本 @ 前缀”之外单独设计。

2. **微信私聊语音/看图**
   - 微信语音依赖 UI 前台和 VB-Cable；
   - 私聊语音需要单独验证搜索/打开私聊；
   - 私聊看图需要扩展 `ImageReference` 和 `VisionInbox`。

3. **QQ 语音训练闭环**
   - 数据集切片、ASR、校对、微调、切换权重；
   - 训练产出与推理服务版本管理；
   - 8GB 显存下的显存/时间基线。

4. **多账号/多平台管理**
   - 当前每个平台一个进程、一个账号；
   - 多账号需要独立配置、数据库和锁；
   - 不建议在没有隔离前共享账号。

5. **打包与部署**
   - 当前是源码 + uv 运行；
   - 可做 Windows 计划任务/服务；
   - 不建议直接把 NapCat 和 webhook 暴露公网。

## 推荐优先级

```text
1. GPT-SoVITS 装好 → QQ 语音条现场验收
2. QQ 网关守护 + 故障自动重启
3. 微信私聊现场验收
4. 私聊白名单管理命令
5. 配置检查/状态命令与结构化日志
6. 真 @ 提醒
```

## 已知限制

- NapCat 是个人号非官方协议，账号可能被风控；只用测试小号。
- 微信 native hook 依赖固定版本，升级微信可能失效。
- 微信语音条需要前台窗口和 VB-Cable，不适合锁屏无人值守。
- GPT-SoVITS 需要独立 Python 环境和 GPU，首次部署/训练周期较长。
- 当前文档不记录真实群号、wxid、token、secret 或聊天正文。
