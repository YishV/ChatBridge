# 聊天记录持久化实施

用户已确认：保存授权群接收到的文字和已确认发送的回复，重启时按群恢复最近 50 条，持久上下文不受原 10 分钟过期限制；完整记录默认保留，历史不触发补发。用户自行启动机器人，本次不启动或重启后台。

## 数据与流程

- 在现有 SQLite 增加 `chat_history` 表和按群索引，迁移幂等，原有控制、去重和投递表不变。成员保存稳定代号及可读昵称，不存原始成员微信 ID。
- 收到合格新消息时，去重认领和 user 历史同事务提交；重复消息不重复入库。模型沉默或失败仍保留群友发言。
- 只有匹配发出回执时，投递确认与 assistant 历史同事务提交；发送失败或未知不写虚假助手发言。
- 启动仅加载仍在授权范围内的群，每群最近 50 条按原顺序进入上下文，保留成员和回复对象。恢复本身不调用模型、不投递、不重建待处理自然批次。
- 内存上下文维持最近 50 条，新消息继续滚动；不再按 10 分钟清掉持久上下文。数据库正文长期保留，模型每次只取受限窗口，每条输入仍限制到原有长度。
- 人设仍按请求从文件读取，成员代号沿用持久随机密钥。已有聊天记录而成员密钥缺失时拒绝生成新密钥，避免同一成员换身份。
- 旧版本没有存下来的正文不回填。暂停、撤群和机器人自发回声不新增用户记录；撤群不自动删除已有存档。

- [x] `qa/service.py`：恢复与格式重建，区分临时模式和持久模式；身份与人设测试保持兼容。

- [x] `settings.py`、`cli.py`：默认每群 50 条，可配置 1～200；生产仅恢复授权群，启动摘要不打印正文。
- [x] 离线测试覆盖独立连接重启、旧记录不过期、未确认回复不入库、历史不触发回复、模型失败仍留用户发言、多成员归属和数据库可查看性。

数据库和备份继续放在 Git 忽略目录。用户可使用 DB Browser for SQLite 浏览 `chat_history` 表；此功能是聊天存档与最近上下文恢复，不包含自动摘要或永久成员画像。
