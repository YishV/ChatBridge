# 群聊天气查询实施计划

> 使用 writing-plans 记录实施范围，使用 subagent-driven-development 执行独立接口任务；不自动提交，不启动或重启机器人。

## 目标与已确认范围

Open-Meteo 免密钥个人非商用接口，当前天气和未来七天预报。群友自然提问，缺少城市或同名地点时先确认；按人设回答、标注来源与数据时间。天气服务只接收城市、坐标和预报参数，不接收群聊文本、身份、密钥。缓存短时有效，失败时不能凭模型知识补造天气。

## 实现边界

1. `weather/client.py`：仅固定 HTTPS 地理检索及预报端点；城市名参数编码；禁重定向；5 秒单次超时、有限响应；验证数值范围、日期、单位，中文 WMO 说明；10 分钟有界内存缓存，拒绝过期缓存降级。多地点不凭昵称推断。
2. `models/client.py`：增加强制 `plan_weather` 结构化工具，抽取天气请求的城市和时间意图；与现有 `decide_reply` 独立。工具不能执行任意 URL/路径。普通聊天继续原调用。
3. `weather/conversation.py`、`qa/service.py`：天气关键词或同成员待澄清上下文才进入计划；只用同群同成员最近历史推断城市。先计划、查询，后在原回复请求中注入已核验数据。失败、城市不明、歧义都有明确提示，不允许输出凭空天气。保留表情与人设。
4. `dispatch/processor.py`：每次物理模型请求都预留配额；一次完整处理遇到暂时错误时整体最多重试一次；各阶段之间复检暂停/白名单。两阶段天气调用不能让原来一次调用配额失真。
5. `settings.py`、`cli.py`、`.env.example`、README：开关、缓存、超时；增加仅本机天气检查命令；不改群授权、数据库结构、人设和语音关闭状态。

## 验证与交付

- 先用虚构数据测试成功、中文城市、多义地点、无城市、同名群友不串位置、失效缓存、坏响应、禁重定向、超时、模型配额、暂停、重试和现有聊天回归。
- 独立接口模块实现后先审规格，再审质量；集成后做全量离线回归。
- 用公开城市做一次实际 API 查询；可做一次不发送微信的模型计划/回复检查，不把它称为群内验收。
- 给出自启命令与示例，不自动运行机器人。私有配置和真实群聊不入仓库。
