# 场景表情包实施计划

> 使用 subagent-driven-development 执行独立素材任务，主流程负责聊天与投递集成；不自动提交或启动机器人。

## 已确认范围

从 aigengtu.com 的 DeepSeek娘图库同步素材信息并按需缓存。模型结合最近群聊、人设选图，每次最多一张，按群冷却、避免重复。图片失败保留已发送文字；发送不明不重试。第一版只用静态素材。

## 接入事实

- 站点官方仓库提供带描述的精选 WebP 镜像，站点和 CDN 当前程序访问返回 403。优先同步站点可读页面；受限时同步官方仓库 README 中的精选图及镜像，不绕过站点限制。
- 当前本机加固组件健康检查报告 `nativeStickerSend=true`，已有 `/SendStickerMsg`，只接收限定 outgoing 目录中的 MD5 文件名 GIF。将单帧图转为单帧 GIF 使用该现有接口，不改动或重启微信组件。
- 接口接受不等于发送确认。只以同群、新产生的本人记录、匹配文件 MD5、正 server_id 为确认依据；未知状态不补发。

## 任务

- [x] 素材模块 `media/memes.py`：固定源同步、索引本地保存、有限大小读取、静态解码、单帧 GIF 缓存；未知 ID/外部 URL/多帧图片拒绝。
- [x] 聊天 `qa/service.py`、`message.py`、`dispatch/processor.py`：启用素材时一次 JSON 请求同时返回文字与已注册 meme_id；无图/坏 ID 仍保留文字；没有素材时保持现有聊天。
- [x] 数据库 `state/store.py`：独立 media_deliveries 保存一次性图片投递、跨重启群冷却/最近使用；只有确认的图片描述进入历史。
- [x] 接入 `wechat/gateway.py`、`wechat/delivery.py`：复用已就绪的静态 GIF 接口，严格目录/文件 MD5、暂停/白名单复检；文字确认后再配图，失败不重发文字。
- [x] 配置与 CLI：`memes sync/list/check`，开关、60 秒群冷却、最近 5 张避重；仅显式同步联网，运行时图片按需取用、失败降级。
- [x] 文档和离线验证：选图/沉默、下载失败、图片回执、撤销/暂停、持久化/重启、旧文本流程回归。
- [x] 本机素材索引同步（19 张）与公开样图 083 的真实下载、单帧 GIF 转换。
- [ ] 场景表情包真实群内发送与服务器回执验收（需授权群现场观察）。

## 验证结果

2026-10-20：离线完整回归 276 项通过；素材同步/校验、单帧 GIF、文字+选图、冷却/避重、回执/失败路径、媒体历史均有测试。收尾修复了 `run --check` 在测试配置下被表情目录解析阻断的问题，并将 `DeliveryService` 测试图库桩补齐 `assets`。公开索引已同步 19 张；样图 083 成功下载并转为 1254×1254 单帧 GIF，已缓存到本机组件限定的 outgoing 目录。真实 `run --check` 报告 `memesEnabled=true`、`memeAssets=19`、`memeNativeReady=true`。真实群内图片发送和回执尚未执行，不能称为现场验收通过。


## 验证原则

先新增行为测试并确认失败，再实现。运行定向与全量离线测试；使用公开样图验证真实下载/解码。群内发送需记录是否真实完成，不能把离线测试称为群内验收。
