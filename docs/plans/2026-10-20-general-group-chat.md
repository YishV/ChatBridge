# 通用微信群文字聊天实施计划

用户已确定：去掉特定游戏用途，先打通通用文字聊天；参与方式为原生 @ 时回答、其他消息结合最近群聊择机接话。模型沿用 DeepSeek。唱歌和原生语音条为后续阶段。

> 后续更新（2026-10-20）：`@`/拍一拍语音条已按独立方案接入（免费 Edge TTS + VB-Cable + 微信 PC 语音图标），自然接话仍为文字；详见 [语音条实施记录](2026-10-20-voice-messages.md)。唱歌和音频文件发送仍未接入。

## 设计与边界

- 只运行已授权测试群。读取层使用固定版本微信与已核验的本机组件，保留 DPAPI 凭据、回环监听和账号校验。
- 普通群消息进入仅内存的群内短期上下文（最多 20 条、10 分钟）；模型只接收当前白名单群的必要上下文，成员以群内匿名标识区分。管理员配置不由聊天修改。
- 被原生 @ 时直接生成简短中文回复。未 @ 的自然参与请求只允许返回 `{"reply": null}` 或 `{"reply": "内容"}`；默认克制，不逐句回应，坏格式视作沉默。无声消息也持久去重。自然参与评估默认至少间隔 30 秒，明确 @ 默认冷却 5 秒，模型调用每群每小时默认最多 60 次。
- 上下文仅在确认服务器发出记录后记入助手回复；发送失败或状态未知不伪造已回复，不自动重发。
- 持续网关启动时记下当前群表游标，不回复旧消息；逐分片按本地 ID 轮询，只有取得正数服务器 ID 的群文本能进入聊天。出现账号/核心版本/监听归属变化即停止。暂停与白名单动态生效。
- 网关只发送文本；未来语音合成、唱歌音频生成和原生语音条发送分别接入，不把“发音频文件”当成“发微信语音条”。
